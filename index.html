// How I run an AI-directed engagement

Verified, not asserted

Every case study below descends from the same discipline I enforce on every delivery across an AI-directed engagement: read the real source, run the real test, capture the real evidence — and disclose what's still broken. AI coding agents write the implementation and the regression tests, under a build constitution I author and a registry that refuses to upgrade a status without attached evidence. My job is requirements, governance, and the final review before anything is called "done" — and, just as importantly, re-checking an agent's own account of its work instead of taking it on faith.

That same discipline, turned on the agents' own claims, is what has caught things like a certification-readiness milestone that had silently regressed from "ready to ship" to "not ready" between two reports, and a consent or safety control that was live at one entry point but never actually wired into the downstream feature it was built to protect. Both are the kind of finding that gets reported, not smoothed over — because the discipline only has value if it survives pointing at your own work.

CASE 01 / SECURITY OPERATIONS

Security Operations Center for a live platform

Live production Tenant-scoped RBAC Hash-chain audit log Vulnerability management

Directed the build of a 68-page production SOC module for a client's platform — tenant-scoped access control enforced server-side at a single real authorization function, a SHA-256 hash-chain audit log that requires human acknowledgement of any detected break, and an authorization-gated vulnerability-scanning pipeline — proven safe through roughly 90 regression tests run directly against live production data.

68admin pages, tenant-scoped
~90regression tests
180+real live vulnerability findings triaged
Foundunacknowledged audit-chain breaks, disclosed not hidden
◆Required access control to be enforced at one real function called from every module — proven by a route-level gate test independent of whether a navigation link even renders, closing the common "hidden in the menu but still reachable by URL" gap.
◆The scanning pipeline checks authorization before the scanner ever runs — an out-of-scope target is blocked with the scanner never invoked, proven by a test rather than asserted in a design document.
◆Designed the hash-chain audit log to never silently self-repair — a detected break requires a human-written acknowledgement by policy, not an automatic "resolved" flag.
◆Disclosed, not hidden: a daily integrity check first surfaced a real, unexplained set of audit-chain breaks and was flagged directly to the client. A later internal audit re-checked rather than restated that figure and found additional breaks in a second account scope that no earlier report had surfaced — the lesson that shaped every later audit on this engagement: re-run the check, don't re-read the report.

Extended it into a second, independent workforce, then directed an AI-on-AI audit that caught a real production bug and a separate agent's scope violation.

10 + 9named agents across two independent workforces

33/0circuit-breaker tests passed/failed, independently re-proven live

◆Designed the governance registry to be structurally fail-closed: a forbidden-function detector tokenizes every agent's own source code on every dashboard load, diffing real code against declared capability — not a one-time audit that goes stale the day after it's run.

CASE 05 / REALTIME SYSTEMS

Realtime multi-user voice & video communications

Live production Low-latency rooms & live events Bug found & fixed same day

Diagnosed a real production bug in a live rooms/events feature where recordings were silently served as audio-only files despite video having actually been captured — reproduced it with browser automation and a media-inspection tool, traced a cross-feature processing coupling, and directed a self-healing fix that corrected every affected historical row with no manual backfill script.

6,700+lines, the core realtime-room dispatch file
160+distinct real server-side actions in that module
1cross-feature bug root-caused and fixed
0backfill scripts needed — a self-healing fix
◆Root cause: an audio-only post-processing function, originally built for an unrelated podcast-style feature, was running unconditionally on every recording from this realtime-rooms feature — silently discarding video that had actually been captured. Fixed by verifying the real file bytes with a media-inspection tool instead of trusting a client-reported flag that could race a page unload.
◆Because the realtime SDK vendor has no token-revocation API, required moderation to be backed by a second, independently-verified enforcement layer — confirmed live to cut a misbehaving publisher's media within roughly ten seconds.
◆Found and closed a real join-time privacy bypass in the same feature area shortly before this case study was written — a reminder that this class of system needs continuous, not one-time, verification.
